[ALEX]: When you try to download a modern single‑page app with a tool that only parses static HTML, you’ll end up with a broken offline copy because the JavaScript that loads additional chunks or API data never runs during the capture phase, leaving those resources missing and the site unusable without a network.
[SAM]: So the tool needs to simulate or at least anticipate JavaScript‑driven requests. How does Website Downloader handle that without actually executing arbitrary code in a browser environment?
[ALEX]: It uses a headless Chrome instance to render the page, waits for network idle, then records every request made—including XHR, fetch, and dynamically injected script tags—so those URLs are added to the download queue before any rewriting occurs.
[SAM]: That makes sense, but doesn’t running a full browser for each download add significant overhead, especially for large sites or batch jobs?
[ALEX]: Yes, the tradeoff is slower download times versus completeness; you can disable the headless mode for purely static sites to gain speed, but then you risk missing lazy‑loaded images or SPA routes that depend on client‑side routing.
[SAM]: Speaking of lazy loading, how does the tool deal with images that are only loaded when they scroll into view, since the initial HTML might not contain an <img> src attribute at all?
[ALEX]: The headless browser scrolls through the viewport or triggers IntersectionObserver events, prompting the browser to load those images, which are then captured just like any other network request.
[SAM]: Once all the files are on disk, the next hurdle is rewriting every reference so the browser looks locally instead of online. What’s the core algorithm for converting absolute URLs to relative paths without breaking things like CDN version hashes?
[ALEX]: The tool builds a map from each downloaded URL to its local file path, then runs a series of parsers—HTML, CSS, and JavaScript ASTs—to find url() tokens, href/src attributes, and fetch arguments, replacing each with the mapped relative path while preserving query strings and fragments that are needed for cache busting.
[SAM]: But JavaScript can construct URLs dynamically, like concatenating a base with a variable; static AST analysis won’t catch those. How does the tool handle those cases?
[ALEX]: It falls back to a runtime patch: after downloading, it injects a small service worker that intercepts fetch events, checks if the requested URL matches any known remote resource, and serves the local copy instead, effectively covering dynamic string building.
[SAM]: Service workers are great for offline fallback, but they also require the site to be served from a secure context. If I’m just opening file:///index.html, won’t the service worker registration fail?
[ALEX]: Exactly, file:// origins don’t support service workers, so the tool also rewrites the page to use a local HTTP server (like python -m http.server) for testing, or it embeds a fallback mechanism that rewrites XMLHttpRequest and fetch calls directly in the page’s inline script before serving the file.
[SAM]: Let’s talk about assets like web fonts. If a site uses @font-face with a cross‑origin source and the font is served with CORS headers that block usage, does the downloader need to do anything special?
[ALEX]: It downloads the font file regardless of CORS because the request originates from the downloader, not the browser; then it serves the font with the appropriate Access‑Control‑Allow‑Origin: * header locally, ensuring the CSS @font-face rule works when the page is loaded offline.
[SAM]: What about preserving the exact visual state, like media queries that depend on viewport width or device pixel ratio? Does simply having the CSS files locally guarantee the same rendering?
[ALEX]: Yes, because the CSS itself is unchanged; the browser still evaluates media queries against the viewport of the offline view. The only thing that could differ is if the site uses window.matchMedia with JavaScript to load different assets—those are caught by the headless crawl and rewritten just like any other URL.
[SAM]: Finally, how does someone integrate Website Downloader into a larger workflow, say, as part of a CI pipeline that validates documentation builds?
[ALEX]: You can run it as a CLI command, specify a URL and output directory, and then use the resulting static site as an artifact; because the tool is open source, you can also hook into its parser events to run custom validation scripts, like checking for missing alt tags or verifying that all service‑worker registrations succeed.
