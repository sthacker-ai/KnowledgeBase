[SAM]: How does the model keep memory usage so low when processing such a long sequence of visual tokens, given that vanilla attention scales quadratically with sequence length?

[ALEX]: It replaces the dense attention matrix with a combination of block‑sparse and linearized attention patterns; the model partitions the visual token stream into overlapping windows, computes exact attention within each window, and approximates cross‑window interactions using a low‑rank kernel trick that reduces the complexity from O(n²) to O(n log n) while preserving the ability to attend to any token when needed for context‑dependent character prediction.

[SAM]: Can you give a concrete example of how the block‑sparse pattern works in practice for a document with mixed text and tables?

[ALEX]: Imagine a page where the top half contains paragraphs and the bottom half holds a financial table; the model creates fixed‑size blocks of 256 tokens, applies full attention inside each block, and then adds a few global tokens that summarize each block, allowing the paragraph tokens to attend to the table’s column headers through those globals without computing every pairwise table‑paragraph interaction.

[SAM]: What trade‑offs does this approximation introduce, especially for tasks that require precise alignment between distant visual elements, like matching a footnote number to its definition across pages?

[ALEX]: The main trade‑off is a slight reduction in fidelity for ultra‑long-range dependencies; however, the model compensates by incorporating a lightweight recurrent memory module that carries a compressed summary of previous pages forward, so footnote references can be resolved with under 0.2 % character error increase compared to the full‑attention baseline while still staying within the memory budget.

[SAM]: Besides the attention redesign, what other architectural changes enable the single‑pass throughput you mentioned earlier?

[ALEX]: The model fuses a shallow CNN stem with a vision transformer backbone, using depth‑wise separable convolutions to extract local texture before tokenization, and it employs a shared query‑key projection across layers, which cuts the parameter count by roughly 30 % and reduces the activation storage needed for back‑propagation during training.

[SAM]: How does the shared query‑key projection affect the model’s ability to learn distinct representations for early versus late layers, which is often important for hierarchical feature learning?

[ALEX]: By keeping the projection shared but adding a small layer‑specific bias and scaling factor, the model retains enough flexibility to specialize per layer while still benefiting from the reduced memory footprint; ablation studies show less than 0.1 % drop in accuracy on the SROIE dataset when the bias is omitted, confirming the approach’s effectiveness.

[SAM]: You mentioned the model builds on DeepSeek OCR as a foundation; what specific parts of DeepSeek’s weights are kept frozen during the efficiency‑focused fine‑tuning, and why?

[ALEX]: The early transformer blocks that capture low‑level glyph strokes and texture are frozen because they are already well‑generalized from the massive pretraining corpus, while the later blocks and the attention‑replacement modules are fine‑tuned to adapt the model to the OCR‑specific token distribution and to learn the new sparse patterns without catastrophic forgetting.

[SAM]: Are there any limitations or failure modes that practitioners should be aware of before adopting this model for production‑critical document workflows?

[ALEX]: The model can struggle with extremely low‑contrast scans or heavily degraded handwriting where the visual signal falls below the noise floor that the CNN stem was trained on; in those cases, a lightweight preprocessing step such as adaptive contrast enhancement or a fallback to a specialized handwriting recognizer is recommended to maintain acceptable accuracy.
