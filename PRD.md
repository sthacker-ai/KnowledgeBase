# Product Requirements Document — KnowledgeBase

**Version:** 4.0 (Nocturne redesign, pipeline resilience, hosting evaluation)
**Last Updated:** July 6, 2026

---

## 1. Product Vision

KnowledgeBase is a **local-first personal learning system** that turns your X/Twitter liked posts, YouTube videos, and articles into a structured, searchable knowledge base — with AI-generated courseware, a wiki, and a knowledge graph.

Everything runs on your own machine. No cloud dependency for content storage. PostgreSQL is used for learning progress tracking and pipeline observability. The project started small and is evolving into a full learning management system — architecture is intentionally kept hybrid (files + PostgreSQL) so content remains git-trackable and Obsidian-compatible.

## 3. Architecture

### Current Implementation Notes

- The shared pipeline order is now: import likes, extract source content,
  transcribe video sources, classify, generate/update courses, update topic
  summaries, build graph, generate hero assets, generate podcasts, export
  Obsidian.
- Video transcription works for native X uploads by downloading the tweet media
  with `yt-dlp` and running speech-to-text. It is not limited to YouTube
  captions.
- If a source already has `course_path`, course regeneration overwrites that
  existing course file instead of creating a duplicate course number.
- Generated audio, images, exported Obsidian vault files, token usage, and
  runtime logs are local artifacts and are ignored by Git.
- Admin mutation APIs can be protected by setting `KB_ADMIN_TOKEN`. **Note:**
  if this is unset, `requireAdmin()` allows every admin API request through
  unauthenticated — always set it before exposing the app beyond localhost.
- **Pipeline resilience (2026-07-06):** `scheduled-daily.js` and
  `run-pipeline.js` are continue-on-error. Each step in `pipeline-steps.js`
  carries `critical` (default `false`) and `retries` metadata; only a step
  marked `critical: true` aborts the run, and `extract`/`transcripts` get one
  retry with backoff for transient network failures. A run's final status is
  `ok` | `completed_with_errors` | `aborted`. A pre-flight check logs an
  early warning if the saved X session is expiring or dead.
- **X session TTL fix (2026-07-06):** `saveCookieSession` previously
  hard-expired the saved `auth_token`/`ct0` cookies after 30 days regardless
  of their real validity, causing Playwright to silently drop still-valid
  cookies and fail with "X session is not logged in." TTL is now
  `X_SESSION_TTL_DAYS` (default 365). Automated headed login
  (`npm run import:x-login`) is blocked by X's bot detection for this
  account — the manual cookie-copy path (`npm run import:x-cookies` after
  copying `auth_token`/`ct0` from DevTools) is the primary, working method.
  See `docs/x-importer.md`.
- **Dev/prod build isolation (2026-07-06):** `next.config.mjs` routes
  `next dev` to `.next-dev` and `next build`/`next start` to `.next` via
  `distDir`, so a production build (e.g. the daily 1 PM prod-deploy task)
  can never corrupt a running dev server's webpack cache, and vice versa.

### 3.1 Data Flow

```
X/Twitter Likes
    → import-x-likes.js (Playwright)
    → data/raw/{tweet_id}.json

YouTube / X Video
    → import-youtube.js / extract-transcripts.js
    → yt-dlp download
    → Groq API transcription (whisper-large-v3-turbo, free tier) — ~10 sec per file
      OR faster-whisper local fallback (CPU, ~20-30 min per file)
    → data/transcripts/{tweet_id}.txt

data/raw/*.json
    → import-x-source.js (Playwright scraper)
    → extracted content saved to raw JSON

Classified sources
    → classify-source.js + OpenRouter AI
    → topic_slug, topic_label assigned

Classified sources + transcripts
    → compile-course.js + OpenRouter AI
    → content/courses/{topic_slug}/course-NNN.md

Courses
    → update-topic-summary.js + OpenRouter AI
    → content/wiki/{topic_slug}.md

All content
    → build-graph.js
    → data/indexes/graph.json

Next.js app reads from:
    - content/courses/**/*.md
    - content/wiki/*.md
    - data/indexes/
    - PostgreSQL (learning_progress, reading_sessions, daily_streaks)
```

### 3.2 AI Provider Chain

Text generation (`scripts/lib/ai-client.js`) is a hardened fallback chain with
a per-run circuit breaker: the first 429/rate-limit from a provider marks it
dead for the rest of that process run so subsequent calls skip straight to
the next one instead of retrying a provider known to be exhausted.

1. **OpenRouter primary** — model set via `OPENROUTER_MODEL_PRIMARY` (currently a free-tier Llama 3.3 70B)
2. **OpenRouter fallback** — model set via `OPENROUTER_MODEL_FALLBACK` (currently a free-tier Qwen3 235B)
3. **NVIDIA NIM** — model list via `NVIDIA_MODELS` (comma-separated, tried in order)
4. **Ollama local fallback** — `OLLAMA_MODEL` at `OLLAMA_BASE_URL` (last resort, always available)

Exact model IDs live in `.env` / the defaults in `ai-client.js`, not here —
free-tier model availability on OpenRouter/NVIDIA changes periodically and
these get swapped without a doc update each time. Check `ai-client.js` for
ground truth.

**Transcription (STT):** Groq `whisper-large-v3-turbo` (free tier) primary,
local `faster-whisper` (CPU) fallback.

**Hero images:** Replicate `black-forest-labs/flux-schnell` (16:9, ~$0.003/image —
this is the one paid-per-call step in the pipeline). Auth via the
`Replicate_API-Key` env var (note the unconventional casing — that's the
literal name the code reads).

**Podcast TTS:** Kokoro 82M via OpenRouter's `/audio/speech` endpoint
(`hexgrad/kokoro-82m`), with an optional Orpheus-FastAPI GPU upgrade path via
`ORPHEUS_API_URL`. (This has changed providers more than once — edge-tts and
Magpie TTS were both used previously and are no longer active; if this section
looks stale, `scripts/transcribe/generate_audio.py` is the source of truth.)

### 3.3 Storage Strategy (Hybrid)

| Data | Storage | Reason |
|---|---|---|
| Courses, wiki, sources | File system (`.md`, `.json`) | Static at build time, version-controllable, Obsidian-compatible |
| Learning progress | PostgreSQL | Mutable, queryable, survives rebuilds |
| Reading sessions | PostgreSQL | Time-series, needs aggregation |
| Daily streaks | PostgreSQL | Incremental updates |
| Pipeline run history | `data/runs/` JSON + PostgreSQL (planned) | Observability; JSON is immediate, DB enables querying |
| AI token usage | `data/token-usage.json` + PostgreSQL (planned) | Track cost per model; JSON is immediate, DB enables analytics |
| AI prompts | `data/prompts.json` | User-editable, hot-reloaded |
| Graph data | `data/indexes/graph.json` | Rebuilt on demand |

## 4. Pipeline Steps

The full, current, 12-step order lives in `scripts/pipeline-steps.js` (the
single source of truth shared by `scheduled-daily.js` and `run-pipeline.js`)
— reproduced here for reference, but that file is authoritative if this
drifts:

| # | Step | Script | Input | Output |
|---|---|---|---|---|
| 1 | Import likes | `import-x-likes.js` | X/Twitter account | `data/raw/*.json` |
| 2 | Extract sources | `import-x-source.js` | raw JSON | extracted text in raw JSON |
| 3 | Video transcripts | `extract-transcripts.js` | video sources | `data/transcripts/*.txt` |
| 4 | Classify | `classify-source.js` | extracted JSON | `topic_slug` added |
| 5 | Compile courses | `compile-course.js` | classified JSON + transcript | `content/courses/` |
| 6 | Summarize topics | `update-topic-summary.js` | courses | `content/courses/*/summary.md` |
| 7 | Build graph | `build-graph.js` | all content + indexes | `data/indexes/graph.json` |
| 8 | Hero images | `generate-course-assets.js` | courses | `public/course-assets/` |
| 9 | Podcasts | `generate-podcast.js` | courses | `public/course-audio/` |
| 10 | Export Obsidian | `export-obsidian.js` | all content | `data/obsidian-vault/` |
| 11 | Upload media to R2 | `upload-media-to-r2.js` | steps 8–9 output | Cloudflare R2 + `data/media-manifest.json` |
| 12 | Commit & push | `git-publish.js` | steps 1–11 output | `git push origin main` → Vercel auto-redeploys |
| — | Daily schedule | `scheduled-daily.js` | Task Scheduler, noon IST | runs steps 1–12, continue-on-error |

## 10. UI Design — "Nocturne" (shipped 2026-07-06)

Full visual identity replacing the earlier light indigo/amber theme. See
`docs/brandguide.md` for the complete token reference. Summary:

- **Dark-first**, indigo-black ground (`#0A0C14`) with an ambient gold+rose
  radial glow; light mode kept as a secondary variant behind a labeled
  toggle pill (bottom-right, every page), default is dark.
- **Typography:** Space Grotesk (display/body) + JetBrains Mono (numerals,
  IDs), both self-hosted via `next/font/google` — no runtime font CDN
  request, works offline after the first build.
- **Glass surfaces:** stat cards and panels layer a translucent gradient
  over the base surface with `backdrop-filter: blur`, gradient-filled
  (gold→rose) numerals and hero headline.
- **Motion:** app-wide page transitions (`app/template.tsx`), staggered
  card entrance animation, animated count-up on dashboard stats, hover
  lift on cards/buttons, animated hero glow — all gated behind
  `prefers-reduced-motion`.
- **Theme-aware D3 graph:** `KnowledgeGraph.tsx` reads its node/edge/label
  colors from the live CSS custom properties at render time rather than
  hardcoded hexes, so `/graph` re-skins with the rest of the app.
- Token-based cohesion pass covers `/`, `/courseware`, `/wiki`, `/graph`,
  `/runs`, `/tokens`, `/filtered`, `/admin` — verified no light-theme-only
  hex colors remain in any page component.

### Known Gaps / Deferred to Next Phase

- **`KnowledgeBase Prod Deploy` scheduled task is currently disabled**
  (confirmed via Task Scheduler, 2026-07-06) — the 1 PM daily prod
  rebuild/restart is not running. `KnowledgeBase Daily Import` (noon daily)
  is active. With Vercel now live and auto-redeploying on every pipeline
  push (Phase T), the local prod server on port 3006 may not be needed
  going forward — worth deciding whether to keep it or retire it.
- **Vercel MCP connector not authorized** — blocks checking actual account
  usage or provisioning resources directly from a session; needs
  authorization via claude.ai connector settings (can't be done from a
  non-interactive session). Vercel CLI (`npm i -g vercel && vercel login`)
  is a connector-independent alternative.
- **`data/transcripts/tmp/`** accumulates temporary downloaded video files
  (~175 MB locally as of 2026-07-06) that are correctly `.gitignore`d but
  never cleaned up — safe to delete manually; not wired into any cleanup
  step yet.
- **Daily automated `git push` to `main` is unattended** (Phase T) — the
  scheduled pipeline now pushes directly to the branch Vercel deploys from,
  with no human review step. Acceptable for this personal project as
  explicitly requested, but worth knowing: a bad AI-generated course or a
  pipeline bug could reach the live site same-day, auto-deployed. Watch
  `/summary` and `/runs` after the daily run for `completed_with_errors`.
- Automated headed X login (`npm run import:x-login`) does not work for
  this account (X bot-detection blocks it) — the manual cookie-copy path
  is the supported method going forward, not a fallback.
