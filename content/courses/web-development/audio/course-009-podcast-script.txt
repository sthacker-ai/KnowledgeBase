The trade‑off is a tiny increase in JavaScript import overhead for the component itself, but the net payload is still lower than hand‑crafted solutions.

[SAM]: Playground aside, how does the library handle reduced‑motion preferences? Does it respect the `prefers-reduced-motion` media query automatically?

[ALEX]: Yes. Each animated component checks `window.matchMedia('(prefers-reduced-motion: reduce)')` on mount. If the query matches, the component skips the animation prop and renders a static version or a fallback fade with zero duration. Developers can also force animation off by passing `disabled={true}` if they need to override the media query for a specific case.

[SAM]: Let’s discuss pitfalls. What are common mistakes developers make when integrating this library, and how can they avoid them?

[ALEX]: One frequent mistake is importing the component from the wrong path, which leads to missing styles because the side‑effect‑free import doesn’t trigger the CSS injection. The fix is to use the named export from the main entry point, e.g., `import { Button } from '@freeanim/ui';` not a deep import like `import Button from '@freeanim/ui/lib/Button';`. Another pitfall is nesting animated components inside elements with `overflow: hidden` that clips transform‑based animations; the solution is to ensure the container has `overflow: visible` or to use animations that rely on opacity instead of translate. Finally, forgetting to peer‑install React 18 can cause version mismatches, so always run `npm ls react` after installation.
