[ALEX]: OpenHuman’s Super Context cuts the average number of clarification turns in a coding‑assistance session by roughly 40% because it injects a real‑time snapshot of the user’s active file, cursor position, and recent clipboard content before the LLM even sees the query.  
[SAM]: How does the system decide which pieces of that snapshot are actually relevant to the upcoming conversation, and what happens if the relevance filter is too aggressive?  
[ALEX]: The context pass returns a JSON payload with fields like {“active_window”:…, “clipboard”:…, “recent_files”:…}. A lightweight scoring step computes cosine similarity between embeddings of each field’s text and a short “topic hint” derived from the user’s opening message; only blocks above a threshold (empirically 0.35) are concatenated into the system prompt.  
[SAM]: If the threshold is set too high, could the agent miss useful context, say, a relevant function defined in a file the user opened earlier but isn’t currently active?  
[ALEX]: Yes, that’s a known trade‑off. The default threshold favors precision to avoid prompt bloat, but developers can lower it or add a rule‑based fallback that always includes the last N files from the watcher, trading a few extra tokens for higher recall.  
[SAM]: Speaking of tokens, how large are these context blocks typically, and what impact do they have on latency when using a remote LLM API like GPT‑4?  
[ALEX]: In our benchmarks, a full context pass adds about 120‑180 tokens on average—roughly one extra sentence—raising the API call latency by ~120 ms on a typical broadband connection, which is negligible compared to the 600‑900 ms model inference time.  
[SAM]: What about privacy? The agent reads the screen, clipboard, and file system; how does OpenHuman ensure that sensitive data isn’t unintentionally sent to the LLM provider?  
[ALEX]: All collection happens locally; the JSON payload never leaves the machine unless the user explicitly enables cloud sync. Developers can toggle individual collectors, and the framework includes a red‑action hook that can mask patterns like credit‑card numbers or passwords before scoring.  
[SAM]: Let’s talk implementation. If I wanted to add a new collector that tracks the user’s current Git branch, where would I plug it in?  
[ALEX]: You’d create a Python class inheriting from BaseCollector, implement the collect() method to run git rev-parse --abbrev-ref HEAD and return a dictionary under the key “git_branch”. Then register it in collectors.yaml under the enabled list; the context‑pass pipeline will automatically call it on each new chat.  
[SAM]: Does the collector run synchronously, or could it block the UI if the Git command is slow?  
[ALEX]: Collectors are executed in a thread‑pool with a 200 ms timeout per collector; if a collector exceeds that, its result is discarded and a warning is logged, keeping the UI responsive.  
[SAM]: What happens when the user switches contexts mid‑conversation, say, from editing a Python file to reading a PDF? Does OpenHuman update the context dynamically?  
[ALEX]: The current design performs a single context pass at chat start; it does not poll for changes. For mid‑session updates, you’d need to trigger a manual “refresh context” command or build a listener that re‑runs the pass when a collector signals a significant change, like a window‑focus event.  
[SAM]: Are there any documented failure modes where the context pass actually degrades agent performance, perhaps by introducing contradictory information?  
[ALEX]: Yes—if the clipboard contains unrelated code snippets, the similarity scorer might still promote them, leading the LLM to suggest irrelevant fixes. Mitigations include weighting recent‑file collectors higher than clipboard and adding a confidence decay based on the age of the collected artifact.  
[SAM]: Finally, what practical advice would you give to a team looking to fork OpenHuman for a domain‑specific agent, like a legal‑research assistant?  
[ALEX]: Start by disabling generic collectors you don’t need—screen capture, clipboard—and enable domain‑specific ones, such as a PDF‑text extractor and a legal‑citation watcher. Then tune the relevance threshold on a small validation set of typical queries to balance prompt size against recall, and always run a local‑only privacy audit before enabling any cloud LLM backend.
